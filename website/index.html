研究判断的共同基础

八项基石原则

每次提问、取证与选择，都能回到这些原则。

  1. 01

    事实与理论支撑判断

    讲清事实、概念与推导，让解释成为可以检验的假设。

  2. 02

    事实优先与独立分析

    区分来源陈述、事实与研究者推断，对每个角色采用相同证据标准。

  3. 03

    判断随证据迭代

    说明什么证据会改变当前解释，再据此调整调查与行动。

  4. 04

    消费者选择与主体激励共同成立

    顾客有选择的理由，参与者也有兑现承诺的动力与能力。

  5. 05

    战略聚焦并作出取舍

    沿着事件与机制找关键堵点，明确服务谁、投入什么和暂缓什么。

  6. 06

    小切口与大纵深

    从一件可调查的小事，追问过程、条件与反例，增加解释的深度。

  7. 07

    最小单元与能力成长

    用白话、示范、操作与反馈，让新人逐步组合复杂研究能力。

  8. 08

    框架服务目标与克制执行

    按当前问题选择方法，完成目标时收束，把框架用在需要的地方。

阅读完整文档 ↗
它适合什么项目？+

主要面向区域公用品牌与特色农产品产业，适合咨询团队、调研负责人、学生与项目参与者。用于其他行业时，先核对主体、供给与渠道机制。

需要把整套规划一次做完吗？+

可以从准备访谈、整理转写、诊断问题或深化某份专题开始。技能按当前任务选择主方法，再围绕具体证据缺口补充内容。

它怎样帮助没有调研经验的人？+

把找谁、怎么开场、问哪次事件、怎样追问、怎样记录与检查展开成可操作的材料，并给完成样例。你也可以要求先示范一个步骤，再根据实际操作逐步加深。

演示中的界面和数据代表什么？+

这是技能方法与输出的交互式样例，使用虚构的产地梨采购项目和教学数据。实际使用时，由你选择的 AI 助手读取技能，结合有权使用的材料开展研究。

项目资料怎样使用？+

技能由本地 Markdown 文件组成。资料如何处理取决于你使用的 AI 助手、工具和账号设置。提供访谈等材料前，按项目授权和所用工具的数据规则处理；本介绍页不上传演示操作，也不接收项目材料。

怎样参与改进？+

在 GitHub Issue 中说明使用版本、要完成的任务和卡住的具体步骤；也可以提交 Pull Request。分享示例时，使用有权公开的脱敏材料。
