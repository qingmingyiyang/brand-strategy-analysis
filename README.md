# 品牌战略分析 · Brand Strategy Analysis

**把专家的研究判断转化为普通人可以执行、能够随证据迭代的调研工作流。**

面向区域公用品牌与特色农产品产业，帮助研究团队完成访谈设计、问题诊断、品牌定位、专题经营方案和行动交接。让执行者知道下一步做什么、为什么做，以及新发现会怎样改变判断。

当前版本 **0.11.1** · 持续迭代中的方法技能 · [MIT License](LICENSE)

[快速开始](#快速开始) · [任务与交付](#任务与交付) · [核心方法](#核心方法) · [文档导航](#文档导航) · [验证与边界](#验证与边界) · [参与改进](#参与改进)

## 适合谁使用

1. 品牌战略团队：把访谈、行业资料和经营事实串成有依据的诊断与方案。
2. 调研负责人：组织多角色、分批次访谈，给执行者可直接使用的材料。
3. 区域产业项目参与者：围绕消费者选择、企业收益、公共支撑和执行条件讨论路径。
4. 研究新手：通过具体问句、示例、分支和检查，学习如何从事实形成判断。

可以从一份录音、一份待审稿或一个尚未讲清楚的问题开始。独立调研或局部修改按当前范围展开；完整总体规划按需覆盖十二章。

## 快速开始

### 1. 获取完整技能目录

在准备存放技能的父目录执行：

```sh
git clone https://github.com/qingmingyiyang/brand-strategy-analysis.git
```

也可以通过 GitHub 的 **Code → Download ZIP** 下载并解压。保留目录中的 `SKILL.md`、`references/` 和 `evals/`，不要只复制入口文件。

这是以 `SKILL.md` 为入口的方法包。自动发现与安装位置取决于所用Agent环境；本仓库未提供通用安装器或插件市场清单。若环境支持本地文件读取，可以先让助手读取完整技能目录中的入口，再开始任务。

### 2. 复制这段启动说明

```text
请读取我提供的 brand-strategy-analysis/SKILL.md，并按需加载相关参考文件。
本轮目标：为明天的本地调研准备可直接执行的材料。
长期目标：找到能够改善经营收益的品牌发展路径。
已有资料：见附件。受访对象包括企业、合作社、政府和消费者。
请先检查关键缺口，再生成分类提纲、追问分支、记录模板和试访安排。
对材料中的归因保留独立判断，说明每个关键问题会帮助决定什么。
```

将其中目标、对象和附件换成自己的情况。若资料尚不齐全，直接说明已知内容和最想弄清的问题，助手会协助探索。

### 3. 随研究进度继续

访谈结束后提供记录，要求提取证据、比较不同角色的说法、生成调研日报，并调整下一轮追问。同一项目保留数据口径、判断状态和未决事项；切换阶段时按需调用新方法。

## 任务与交付

| 你现在要做什么 | 建议提供什么 | 可以得到什么 |
|---|---|---|
| 准备批量访谈 | 研究目标、对象线索、时间与人数约束 | 分层安排、招募与替补办法、分类提纲、记录模板、试访校准 |
| 整理当天录音 | 转写、来源、日期与对象角色 | 固定日报、事实与观点区分、冲突、反证和下一轮任务 |
| 诊断产业或品牌问题 | 目标、交易事件、现况资料和经营记录 | 一句话诊断、机制链、主要堵点、替代解释与补证计划 |
| 比较竞品或选择定位 | 本地线索、目标市场、候选对手与供给能力 | 同口径比较、价值主张、大单品候选与验证条件 |
| 深化一份专题 | 已确认定位、相应业务资料和资源约束 | 经营主体、收益与成本、试点、执行材料及验收办法 |
| 审查或改写报告 | 原稿、读者、本轮范围和反馈 | 问题依据、定向修改、结构化论证与剩余缺口 |
| 制作决策汇报 | 已有研究、待决事项和格式要求 | 汇报结构、逐页内容；有相应工具时再制作演示成品 |

### 可以直接提出的任务

```text
我准备访谈100个人，执行者没有调研经验。请先设计分层、批次、分类提纲、追问规则和复盘方法，说明人数安排的依据及局限。
```

```text
材料里大家都说品牌名气不够。请围绕最近的交易失败记录检查这个归因，比较其他解释，再给出下一轮补访问题。
```

```text
基于已确认定位，只深化电商专题。请把内容、成交、履约、售后和复购串起来，核查经营是否成立，并提供执行材料。
```

```text
请审查这份交易中心方案。重点检查真实付费需求、运营主体、单位经济和设施投资的必要性；先交审查结果。
```

## 核心方法

研究主线：**明确目标 → 获取事实 → 暂定诊断 → 针对性补证 → 比较选择 → 执行与验证。** 新证据可以使流程返回前一步，已确认事实和完成的工作继续保留。

### 事实优先并持续修正

用户、专家、政府、企业和消费者都可能有信息局限与利益立场。先提取事件和证据，再检验归因。桌面研究可以帮助启动，现场记录用于继续验证；材料不足时交代暂定判断及补证办法。

### 小切口与大纵深

从一笔订单、一次拒购或一处合作冲突进入，持续追问发生过程、持续条件、替代解释及设计必要性。例如采购者压价，先比较同规格交易条件，再追查品质稳定、使用成本和分级激励，最后决定验证哪项改进。每层都服务同一个问题，具体步骤与练习卡见[论证与表达](references/writing-and-structure.md)。

### 最小单元

标准是交给没有经验的人，照着材料也能完成。每项执行任务补齐准备、操作、分支、示例、检查与异常处理。比如访谈消费者，要写到访谈谁、怎么开场、怎样追问、记录什么以及何时需要核验。缺少真实资源或专业资质时写清取得条件与交接。

### 同一结构支持比较

本地与竞品按相同维度及口径分析，结论由事实和机制支撑。正文、口头汇报、PPT和执行手册按场合调整节奏，保留关键限定与完整操作。

### 用理论提出可以检验的问题

按问题使用消费者研究、品牌认知、产业组织、交易成本和共同治理等方法。理论要转成问句、证据、反证与行动，具体见[理论支撑链](references/theory-chain.md)。

## 按任务组织工作

| 方式 | 什么时候使用 |
|---|---|
| 提示链 | 边界清晰、步骤固定，依次产出并检查 |
| 路由 | 按输入类型、报告类型和进度选择方法 |
| 并行化 | 独立研究或提取任务可以分工，由主管统一口径并综合 |
| 主管与工作者 | 路线尚不确定，根据新发现动态派工与调整 |
| 评估与优化 | 质量标准明确，采用独立反馈和定向修订 |

多Agent按环境权限、角色、模型及资源约束使用；简单任务直接执行。任务数量和评估轮次依据价值调整，多Agent一致不能代替独立证据。用户决定目标及资源取舍，主管负责证据核验与专业论证。具体见[工作组织与额度控制](references/agent-orchestration.md)。

每次收口明确区分**验收通过、阶段性交付、等待补证和预算暂停**，保留继续工作的入口。

## 报告交付结构

完整委托可以形成 **1+4+1**：

| 产物 | 覆盖内容 |
|---|---|
| 1份总体报告 | 十二章覆盖行业、本地、定位、工程、能力、产品、认知、推广、市场机制、企业生态、政府支撑和三年行动 |
| 4份专题 | 供应链与交易中心、内容与生态电商、产地场景、渠道策略与运营 |
| 1份决策汇报 | 核心问题、策略依据、经营安排、资源责任与待决事项 |

专题可独立委托。工程按证据判断采用、试点、后置或不适用；渠道方案是否包含门店，取决于实际经营条件。

## 验证与边界

本项目处于 **0.x 方法迭代阶段**。入口结构、相关文档链接和分发包做过检查；评估案例包含待运行场景，尚未完成系统的跨模型测试、真实新手执行验证或多Agent效果验证。详见[变更记录](CHANGELOG.md)。

1. 真实调研、数据、经营结果及授权需要用户或执行团队提供，公开资料不能替代所有现场核验。
2. 技能提供方法与模板；网页检索、录音转写、并行执行和PPTX制作依赖运行环境，不能承诺所有平台均已适配。
3. 演示参考包含HTML母版；可编辑PPTX需相应制作工具，HTML文件不能当作PPTX交付。
4. 新版本需要实际加载后才生效。版本识别不自动安装、覆盖其他副本或更新已发布报告。
5. 品牌资产估值、专业认证和单纯视觉制作各有专门条件，具体范围按委托确定。
