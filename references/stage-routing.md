# 报告类型与进度路由

接到任务先识别当前任务及进度；涉及报告时再判断报告类型。独立调研、提纲准备和记录分析可直接进入对应方法。依据当前请求、文档正文、现有产物和用户确认状态判断，文件名只作线索。无需让用户先学会本技能的分类。

## 涉及报告时识别类型

用户只要求调研设计、访谈执行或记录分析时，直接进入下方对应进度，不要求先确定报告。大规模或多人访谈须读取fieldwork的研究安排及跨访谈比较部分，交付分层招募、分类执行包、记录校准和批次调整；不止生成问题列表。

| 类型 | 典型任务信号 | 主工作流与首选参考 |
|---|---|---|
| 总体报告 | 行业、本地、定位、发展目标、十大工程、全产业机制 | W0；master-plan；涉及研究时W1，定位时W2 |
| 内容与生态电商 | 选品、内容、直播、订单、履约、售后、复购 | W4；[电商专题方法](ecommerce-report.md)；脚本素材阶段加[电商内容最小单元](ecommerce-content.md) |
| 产地场景 | 到访、品鉴、参观、产地消费、体验运营 | W5；[产地场景方法](origin-scenes.md)与[协作式追问](collaborative-inquiry.md) |
| 渠道策略与运营 | 批发、经销、餐饮、商超、团购、试供、动销或门店 | W6；special-reports的渠道部分 |
| 供应链与交易中心 | 集采、分级、仓配、集运、交易服务、结算与设施 | W3；special-reports的供应链部分 |
| 结题与决策汇报 | 汇总已有报告、面向领导决策、凝练核心问题 | W8；确认总体与专题基线，按需读相关结论 |

电商订单中的仓配问题可由W4牵头并调用W3相关环节，不能因为出现物流一词就重做整份交易中心报告。多个报告同时委托时划分各自范围和共享基线，当前优先处理用户指定项或阻断其他工作的依赖。明确请求优先于自动分类。

## 按当前进度选择方法

| 当前进度及已有证据 | 此时优先加载的方法 | 下一步交付 |
|---|---|---|
| 刚立项，背景或边界缺失 | project-intake；对应报告入口 | 简短问询、已有背景回述、本轮任务 |
| 准备本地调研，尚无现场材料 | fieldwork的本地、提纲与问卷部分；reasoning-and-evidence | 按主体可直接使用的提纲、问卷、记录表和取证安排 |
| 已有录音或当天记录 | fieldwork的录音处理与日报 | 固定日报、证据冲突、下一轮具体追问与探索 |
| 本地线索已形成，外地证据不足 | fieldwork的外地比较；W1 | 竞品选择、对应假设的调研任务和可比指标 |
| 正在接触项目或诊断问题 | [目标与主要矛盾诊断](problem-diagnosis.md)；W1；协作式追问 | 目标、关键要素、最大堵点、主要矛盾和一句话结论；未知处具体追问 |
| 诊断已有依据，正在选方向 | reasoning-and-evidence；W2 | 候选路径、区分点与大单品检验 |
| 定位已确认，专题尚待深化 | 对应W3至W6；special-reports；output-contracts | 经营设计、成本收益和零经验者可执行的操作包 |
| 已有结构，正在写章节或逐页内容 | writing-and-structure；对应报告方法 | 统一结构的详细正文、表格与素材说明 |
| 已有稿件，收到修改意见 | W7；受影响部分；writing-and-structure | 修改意见到问题的映射、局部修订及一致性检查 |
| 正在凝练结题或排行动 | W8或W9；writing-and-structure或output-contracts | 决策论证、资源责任与行动交接 |
| 内容已定，需要排版或成品 | 对应产物技能；已确认内容基线 | HTML、PPTX或DOCX成品及针对性检查 |

同份报告不同章节可能处于不同进度，按当前负责部分处理。草稿里写有已完成不能直接证明现实行动已完成；用用户确认、来源记录和实际产物判断。发现局部缺证据时只补影响当前决定的部分，不把成熟项目退回起点。

## 方法和外部技能如何调取

本包的参考文件承担默认能力，运行不依赖私人技能安装。先读取当前任务最相关的内容，随证据或阶段变化再扩展；不一次加载全部方法。

若环境已提供适用技能，再按产物使用：复杂判断用thinking-model或等效推理方法；正式文字用writing或适用汇报方法；HTML品牌演示用brand-html-ppt-design；原生PPTX用ppt-master；DOCX格式用word-doc-format；问卷结果需要表格分析时用可用表格工具或技能。先确认工具与技能存在并读取其说明，未安装时使用本包方法完成可交付部分，明确格式能力边界。

旧版品牌与汇报方法已选择性吸收到本包相应参考，不再连锁加载旧技能。具体项目通过[私人案例库](private-case-library.md)按需读取，保留来源、时期和验证状态，不能套用于其他产区。外部技能不得覆盖本项目已确认的数据基线、最小单元定义与当前任务范围。

## 简短路由记录

复杂或持续任务记录：报告类型、当前进度、判断依据、已确认基线、当前缺口、优先方法、下一交付。可以写在既有任务记录中，无需另建空表。面对用户只简要说明本轮将处理什么；分类存在会改变方向的歧义时才问。

## 用户原话与独立动作

以下是识别示例，不按关键词机械匹配；同时检查上下文、材料与明确范围。动作接口见[工作单元](work-units.md)。

| 用户原话 | 优先动作 | 保持的边界 |
|---|---|---|
| 明天去调研，先问些什么 | 按对象准备访谈、记录表与取证任务 | 不要求先说清根本问题 |
| 今天录音回来了 | 提取证据、日报与后续追问 | 原话中的归因保持待检验 |
| 当地都说名气不够 | 追问近期交易事件并诊断堵点 | 不直接进入传播方案 |
| 导师说没有思想 | 检查目标、因果链、主要矛盾和论证 | 不仅润色措辞 |
| 这个定位凭什么成立 | 回查需求、竞争差异、兑现能力与反证 | 不先改口号 |
| 先改电商这一部分 | 读取电商稿与反馈，定向修订 | 共用基线，局部补证 |
| 产地想建一个体验中心 | 核验到访需求、场地、运营主体与试办 | 建设设想不当作已定事实 |
| 有没有类似案例 | 按约束检索授权可用案例并比较适用性 | 可独立完成，不强行全流程 |
| 帮我把这页写清楚 | 检查论证后生成该页正文与配图说明 | 证据缺失显式指出 |
| 下一步具体怎么做 | 生成最小单元操作包 | 不质疑用户动机，不虚构资源 |

高频原则在入口保留；深度方法按具体问题调用。方法的触发、限制与更新分别由本路由、对应方法文件和方法更新机制维护，避免在多个位置复制同一细则。

## 理论按问题加载

研究提纲、品牌认知、产业诊断、合作机制和价值链升级任务，按[理论支撑链](theory-chain.md)的选择入口调用对应模块；一般文字修改无需加载。

## 多轮对话持续使用

同一品牌项目的后续消息默认延续本技能。每轮先对照当前目标、报告类型、进度、已确认基线与未决问题，判断是补充、纠正、追问、修改还是阶段切换，再使用相应方法。无需用户重复点名，也不因收到零散意见退回通用闲聊或脱离既有约束。

已读取且未变化的方法继续执行，不必每轮重复读全包；切换任务阶段、新方法出现、相关规则更新或上下文不足时，重新读取对应参考。缺失重要上下文时回查项目摘要与证据，不假装记得。将完成单元、下一交付、变更和未决项同步到既有项目状态。

用户明确转入无关任务时暂停品牌流程，不把品牌框架套到所有对话。持续调用体现为方法和基线连续生效，不要求反复向用户报告技能名称。


每轮的持续调用先执行[版本刷新规则](method-updates.md)：核对权威目录版本，变化后刷新入口与当前方法，再判断阶段；无需重复已完成研究。

## 执行组织

确定业务方法与工作单元后，按[工作组织与多Agent调度](agent-orchestration.md)选择串行、并行或动态派工。路由不等于启动Agent；委派时在工作卡中补齐依赖、权限、来源、预算及停止条件，由主管综合验收。
