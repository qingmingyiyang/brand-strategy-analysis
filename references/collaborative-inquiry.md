# 事实优先与协作式追问

贯穿诊断、定位和专题设计。目标既是完成有依据的方案，也帮助用户理解自己如何作出判断。先了解事实，再共同提炼想法；判断可以暂定，事实变化时及时修正。

## 一个可反复使用的对话循环

1. **回述想法**：用简短语言概括用户想实现什么、为什么看好它，区分用户原意与助手推断，给用户纠正空间。
2. **追问事实**：请用户描述具体人、事、地点和记录。问最近发生过什么，比要求概括优势更容易找到真实线索。
3. **提炼命题**：把想法写成某类人在某条件下会因某价值采取某行为，注明依据和未知。表达清楚不等于已证明。
4. **共同检验**：比较替代解释、替代方案和可能反例，邀请用户判断哪个条件最关键，并简要解释它为什么影响选择。
5. **确定下一步**：形成能区分判断的访谈、观察或试办；已知材料足够时直接完成相应设计。
6. **反馈学习**：取得新证据后说明原先的判断、事实变化、现在的调整及可迁移的判断方法，不只交最终结论。

## 由繁入简再由简入繁

用户要学习研究方法、新人接手工作，或某个理解缺口已经影响行动时使用。本方法嵌入上面的对话循环：追问、解释和练习服务同一个研究任务，不另开一套课程。

调研初学者可按[进入、沟通、梳理、发现四阶段](fieldwork.md#调研初学者的四个阶段)识别学习卡点，选择一个动作带练。能完成该动作再增加比较、机制及验证条件，发现新疑问时返回所需阶段；已有能力直接复用。

由繁入简，是从复杂任务中找出当前决定所依赖的基本关系；由简入繁，是把已经理解的基础组成能完成工作的单元，再增加条件、分支和单元之间的关系。简化保留影响判断的关键条件，避免把暂定解释教成永远成立的口诀。

### 从整体目标倒推当前基础

先用一两句话说明最终要解决什么、当前卡在哪一环、这轮学会什么就能前进一步。例如，要决定怎样提高经营收益，眼前先学会取得一条可核验的交易记录。高层起点是任务目的和整体关系，随后落到一个具体动作；不用先讲完整理论谱系。

依据用户已有说法或产物判断起点。没有信息时给一个低负担的尝试，或询问最影响行动的卡点；未提到某个概念不等于不懂。将当前问题向下拆成必要的概念、关系与动作，直到能用熟悉的话讲清，并有可观察的完成结果。

### 从当前理解台阶向前推进

1. **讲清一个基础。** 用白话说明它是什么、为什么影响当前任务，再给一个具体例子。必要时用一组对照说明适用条件。例如，同样叫一箱货，重量和送货条件不同，价格就不能直接比较。
2. **示范一个小动作。** 展示如何从材料中找信息、填到哪里、怎样检查，保留做出选择的理由。素材沿用真实输入；自拟材料标为教学示例，研究记录只接收真实证据。
3. **让用户完成下一小步。** 优先使用手头任务，让他补一个字段、选一个追问或解释一个差异。已交付的实际工作也可以作为观察依据，无需额外出题。
4. **针对表现反馈并回扣目标。** 指出已经做对的地方、具体缺口及它怎样影响判断；给出修正示范或下一动作。会操作但说不清理由时，用一句追问补理解；会复述但做错时，回到具体材料示范。

循环保持短：围绕当前卡点先形成一个能检查的小产物，掌握后可以继续组合下一步。用户暂未回应时保留练习入口，继续完成不依赖回答的已授权工作；只要求成稿或时间紧时，先交可用材料及必要说明，后续再教学。

### 从基础组装单元再进入复杂应用

同一小产物逐步增加复杂度。先示范，再让用户补全，随后减少提示，最后换一个情境检查能否迁移。进阶依据实际表现与任务需要：能完成当前动作并知道关键理由，再增加一项条件、一个分支或一个上下游关系；失误暴露哪一层缺口，就回到那一层。不同人理解与操作的节奏可以不同，不设固定教学轮数或考试门槛。

以下为连贯教学示例，目标是研究卖不上价的原因，所有情况均为假设：

| 层次 | 基础与组装关系 | 当轮可做的动作及检查 |
|---|---|---|
| 基础 | 报价是卖方想卖多少，成交价是实际卖了多少；研究什么就要保留相应性质 | 在一段材料中分别标出报价、成交和未知；只看到价目表时不能填实际成交 |
| 记录单元 | 时间、规格、数量、价格性质与交付条件合起来，才能描述一笔交易 | 按示范补齐一条记录，缺失项写明向谁取证；不靠猜测补成完整表 |
| 比较单元 | 两条记录回答同一个问题且条件可比，才可能解释价差 | 第二条记录含配送而第一条不含时，指出条件差异并补同口径资料；暂不判定品质导致价差 |
| 机制与设计 | 多条可比记录和相关主体证据用于比较原因；选定原因后再组合干预与验证 | 若稳定分级后仍卖不上价，检查需求、识别、渠道和成本等解释，选择能区分它们的下一动作；不从一个案例直接推出建设项目 |

单元组合要写明前一单元交出什么、后一单元拿它决定什么。最后邀请用户用自己的话解释一次选择，或在相邻场景完成同类动作，观察理解与迁移；不把能背术语当作掌握。

### 把专家省略的转折教出来

新人能复述步骤却不会选下一动作时，取当前任务中一个真正困难的判断，不再增加术语。让有相关经历的人还原一次具体事件：当时有哪些选择、注意到哪条不寻常线索、原本预计接下来怎样、什么使他改了动作、后来结果如何。追问如果少了或换了这条线索还会不会这样做，区分当时知道与事后才知道；用对应记录回查当时的线索、选择和结果。

把示范压成情境 → 线索 → 判断 → 动作 → 实际反馈 → 失效条件。紧接一个近似情境，只改变影响判断的关键条件，让新人指出下一动作应怎样变，再用原始材料纠正。可沿用[续单与拒单示例](fieldwork.md#同样不续单怎样走向不同动作)：先示范验收失败怎样引出分级核验，再让新人处理验收合格但付款条件改变的分支。掌握后移去提示，换一个品类观察用户能否独立运用。

此处分别借鉴[ACTA认知任务分析](https://web.mit.edu/16.459/www/Militello98.pdf)对困难步骤、线索和新手易错处的提取，以及[认知学徒制原始报告](https://ocw.metu.edu.tr/pluginfile.php/9107/mod_resource/content/1/Collins%20report.pdf)的示范、支架与逐步撤除。当新人卡在判断转折时，取用这一带练方法。

### 随反馈返回更高层修正

回退既可以补基础，也可以修正问题本身。新记录若显示低价同时伴随更低成本和更高利润，先回到整体目标判断应该研究售价还是收益，再决定后续取证；不能为了走完原来的教学台阶继续证明售价过低。

当用户能完成当前任务所需动作、识别关键缺口并知道何时求助，就收束这一轮。资质、授权、资源和专业判断的交接仍按[最小单元契约](output-contracts.md)处理。持续任务只在已有项目记录中简记已掌握、当前卡点、下个小动作与关键证据，下一轮从此接续。

## 在哪些节点主动问

用户提出未经展开的想法、关键事实缺失、不同路径投入差异明显、来源发生冲突、试办结果与预期不符时，主动发起有针对性的问询。这里的短轮问询用于与用户共同设计和带练；实际访谈按调研主方法准备并把握完整交流机会。按用户当前理解和决策依赖安排问题，把紧密相关的事项放在一起，说明各问题如何影响下一动作。

| 情况 | 示例追问 | 帮助用户学会什么 |
|---|---|---|
| 想建一个场景但还没说依据 | 你最希望哪类人来了以后发生什么变化？最近有没有人表现出这种需要？ | 从设施名称回到顾客与结果 |
| 认为本地资源独特 | 哪项特点已经有证据？消费者能感知它吗？没有这个特点的人会选择什么？ | 分开资源差异与购买价值 |
| 想扩大投资 | 现有小规模试办已经证明了什么？还有哪个条件没证明却决定能否赚钱？ | 找到扩展前的关键假设 |
| 用户也不知道问题在哪 | 能否按最近一次接待或交易从开始讲到结束？哪一步最费时间或最容易出错？ | 从事件与流程发现问题 |
| 多个方向都想做 | 如果这一阶段只能保留一个，你最看重哪个结果？什么事实会让你换选项？ | 形成取舍标准并允许被证据修正 |

提问时说明它将帮助决定什么，并先贡献已有分析、可选解释或证据线索。避免故意隐藏已知答案、把执行责任推给用户，或用诱导性问题让用户确认助手预设方案。用户说不知道时，提供取得事实的方法或可比较的假设。

## 提问与执行的配合

### 调用用户的系统设计能力

与AI配合设计研究时，邀请用户共同界定目标、系统边界、流程、角色、决策接口、反馈与资源取舍。AI先依据已知材料画出简要的目标—流程—角色—假设—证据关系，指出关键未知，先完成对象安排、提纲、字段及验证分支的可审阅草案。用户用现场知识校准关系与优先级，并确认目标、边界、资源和关键取舍；AI据此完善研究材料与方法，已确认部分直接复用。事实陈述仍需核验，研究设计责任由AI承担。

围绕当前关键接口提出具体问题，例如这一步谁有权改变、谁承担后果，或哪份结果能让你改变选择；说明回答会怎样改变访谈对象和取证。用户暂不熟悉系统设计时，用一次真实流程逐步示范，给可选择的草案，不要求用户先交完整系统图。关于对象、知识与假设的具体方法按[访谈设计](fieldwork.md#2-主动追问与提纲设计)相关章节取用，已有设计直接复用。

### 将共同设计落实为行动

多询问用于共同思考，不为每个可逆细节加审批。已明确授权且事实够用的整理、分析、写稿继续完成；等待回答时推进不依赖它的工作。用户要求直接给稿时先交带有证据边界的版本，再列影响下一轮的关键问题。对于决定方向的缺失事实，保留相关结论为条件性判断。

在当前环境有异步问询工具时优先使用它；没有时在合适的对话节点提出简短问题。一次回答用于更新已知事实和假设，不反复询问同一内容。

## 引导用户聚焦并推进到底

用户连续提出多个方向时，先回述它们共同服务的目标，区分当前决定、必要前提和后续议题。依据目标影响、证据缺口与实施依赖推荐一个具体切口，并解释选择理由；方向不清且会改变成果时，用一个关键问题帮助用户取舍，例如本次先要决定卖给谁，还是验证现有客户为何不复购。用户暂不能选择时，先做可逆的事实整理与探索，不代替用户确认重大方向。

每轮围绕当前主问题推进一层：已经知道什么、哪些解释仍可能成立、哪条证据最能区分它们、下一步如何取得。提问服务于这个推进，不连续抛出宽泛问题。用户新增议题时说明它与主线的关系；影响关键前提则调整方向，属于后续工作则简记待办并继续当前问题，用户明确改变目标时同步更新范围。

阶段结束回扣原问题，给出当前结论及证据边界、剩余缺口和可执行的下一步。不能把不断追问当作完成分析，也不能开头承诺多个问题却只交付第一项；无法完成的部分交代原因和继续入口。短任务用简短段落即可，不强制新增记录表。

## 共同思考记录

必要时在已有项目记录中保存：用户原始想法、已知事实及来源、提炼后的命题、尚缺证据、替代路径、用户选择理由、下一验证动作、结果和判断修正。日常短任务用几句话即可，不额外制造文书负担。

## 主动补充用户视角盲区

沿当前问题检查是否遗漏了相关主体、关键环节、替代选择、成本、时间变化或反例。把确实影响判断的缺口带给用户，同时提供已有分析和取证路径。

说明当前判断 → 指出遗漏及依据 → 解释它怎样改变选择 → 给出验证或调整动作。例如：现有方案已讲清消费者价值，下一步需要核算渠道参与条件。扣点、退货和账期会影响渠道净收益，先补同口径收益表，再决定铺货激励。

用户暂不清楚时，给材料模板、候选解释或示范；新证据改变判断时，说明改变的依据，并更新方案。决策权和证据标准沿用技能入口。
