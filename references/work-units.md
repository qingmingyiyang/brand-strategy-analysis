# 可独立调用的工作单元

工作单元是方法的执行与交接接口。按当前请求选择单元，可单独完成，也可串接；无需把所有单元走完。工作单元内部持续拆到零经验者照做能完成，具体标准以[交付契约](output-contracts.md)为准。

## 统一工作卡

| 字段 | 写什么 |
|---|---|
| 进入条件 | 用户信号、当前进度、要解决的具体问题 |
| 输入 | 必要事实、来源索引、已确认决定与资源；区分必要输入和可后补输入 |
| 操作 | 按顺序使用什么材料、执行什么动作、记录到哪里；分支采用可观察条件 |
| 必要追问 | 当前缺什么、向谁问、原句如何问、答案怎样改变判断 |
| 输出 | 可直接使用的正文、表格、脚本或素材及完成样例 |
| 验收 | 如何检查结果；哪些缺口使结果仍属暂定或无法执行 |
| 缺失处理 | 可先完成什么、暂不能判断什么、补证方式与返回步骤 |
| 下一步交接 | 传递哪些证据、结论、限制与未决项；何种条件进入下一单元 |

字段可融入已有文稿，不要求重复生成空卡。具体方法由下表链接文件维护，工作卡不复制整套方法。

## 单元选择

任务与进度的对应清单统一见[阶段路由](stage-routing.md)。本文件只维护执行接口和诊断交接示例；业务方法由相应参考文件维护。

## 完整示例：问题诊断单元

1. 在项目摘要记录用户要实现的结果和衡量口径。目标未明时问：这次最需要改变哪个结果，怎样才算有改善？不能把建园区直接当作最终目标。
2. 从材料提取具体事件，逐条记录主体、动作、结果、时间和来源编号。把受访者归因另列为来源陈述。
3. 按目标实现过程串接事件，列出候选堵点，比较各堵点对结果的影响。缺规模依据时标明无法排序，安排补证。
4. 对候选关键堵点追问：过去试过什么？在哪一步没继续？谁承担成本？谁得到收益？哪两个要求目前无法同时满足？记录回答及其改变的判断。
5. 输出一句话诊断、支持证据、替代解释、可推翻条件和补证表。补证表字段：待确认问题、对象、具体问句、所需记录、答案对判断的影响。
6. 检查是否从名气不足直接跳到加强宣传，是否把同一来源多次复述当成独立佐证。发现跳步则回到对应事件补证。
7. 交给定位单元时传递目标、约束、证据编号和未决项；尚待验证的诊断保持暂定，不能在专题中变成既定事实。

格式样例：为实现〔确认目标〕，当前关键堵点暂判为〔阻碍〕，可能由〔要求A〕与〔约束B〕的冲突持续造成。依据〔证据编号〕，仍需核验〔缺口〕。占位符需用真实材料填写，样例本身不构成事实。

## 执行组织与复用

实际委派或交接时，用上方工作卡说明输入、责任和验收；调度条件统一见[阶段路由的执行组织](stage-routing.md#执行组织)。

已有提纲、记录表和模板适用时直接复用，填入当前项目事实。开发可复用测算模块、演示组件或代码接口时，再检查现有组件的说明、输入输出、依赖和使用实例；沿原有接口适配，缺口明确后补充实现。验证过且有重复使用价值的成果，在已授权范围内登记用途与调用示例。
